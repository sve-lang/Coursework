# Оценка эффективности нового алгоритма рекомендаций в приложении коротких видео (A/B-тест)

## 📌 Описание проекта
Развлекательное приложение с бесконечной лентой коротких видео монетизируется через подписочную модель. Чем глубже пользователь вовлекается в просмотр контента, тем выше вероятность его регистрации и последующей оплаты подписки.

Команда разработки создала новый алгоритм рекомендаций, призванный показывать более релевантный и интересный контент. **Цель исследования** — провести полный цикл A/B-тестирования: от разведочного анализа исторических данных и дизайна эксперимента до проверки корректности сплитования и оценки статистической значимости изменений.

В работе использованы три набора данных:

2. `sessions_project_test_part.csv` — срез данных первых дней эксперимента для оперативного мониторинга корректности сплитования.
3. `sessions_project_test.csv` — полные логи за весь период проведения A/B-теста.

**Основные поля:** `user_id`, `session_id`, `session_date`, `session_start_ts`, `install_date`, `session_number`, `registration_flag`, `page_counter`, `region`, `device`, `test_group`.

## 🔍 Ход исследования и ключевые инсайты

### 1. Разведочный анализ исторических данных (EDA)
* **Динамика аудитории:** Наблюдается уверенный рост DAU с середины августа с выходом на плато на уровне **12 500–17 500** активных пользователей в день (и ~900–1 200 регистраций ежедневно). После 11 сентября зафиксировано сезонное снижение общего трафика.
* **Доля зарегистрированных пользователей:** В пиковые периоды доля авторизованных пользователей составляла около **8%**, а при снижении общего трафика выросла до **10–12%** (отсев случайных посетителей при сохранении лояльного ядра).
* **Выбор целевой метрики:** В рамках первой сессии пользователи чаще всего просматривают **2–4 страницы** (мода — 3 страницы). Чтобы избежать искажения от выбросов при расчете среднего числа страниц, в качестве целевой прокси-метрики выбрана **доля «успешных» первых сессий (`good_session`)** — сессий, в которых пользователь просмотрел **4 и более страниц** (`page_counter >= 4`). На исторических данных этот показатель держится на уровне **31–33%**.

### 2. Дизайн A/B-теста
Для проверки гипотезы о росте вовлеченности рассчитаны параметры эксперимента:
* **Базовый уровень целевой метрики ($p$):** `0.30` (30%)
* **Минимальный детектируемый эффект (MDE):** `+3%` относительных (до 30.9%)
* **Уровень значимости ($\alpha$):** `0.05`
* **Мощность теста ($1 - \beta$):** `0.80` ($\beta = 0.20$)
* **Необходимый размер выборки:** **41 040** уникальных пользователей на каждую группу (82 080 суммарно).
* **Расчетная длительность теста:** **9 дней** (при среднем историческом трафике **9 907** пользователей в день).

### 3. Мониторинг корректности эксперимента
Проверка логов первых дней эксперимента подтвердила высокое качество сплитования:
* **Равномерность трафика:** В группу A попало 1 477 пользователей (50.19%), в группу B — 1 466 пользователей (49.81%). Относительная разница составила **0.74%** (менее допустимого порога в 1%).
* **Независимость выборок:** Пересечений `user_id` между контрольной и тестовой группами не обнаружено (**0 пользователей**).
* **Баланс по сегментам:** Распределение пользователей по типам устройств (*Android, PC, iPhone, Mac*) и регионам (*CIS, MENA, EU*) в обеих группах идентично (отклонения долей не превышают 1–2%).

### 4. Анализ итоговых результатов A/B-теста
Сформулированы статистические гипотезы:
* **$H_0$:** Новый алгоритм рекомендаций не влияет на вовлеченность пользователей ($p_A = p_B$).
* **$H_1$:** Новый алгоритм увеличивает долю успешных первых сессий ($p_A < p_B$).

**Результаты эксперимента:**

| Метрика / Показатель | Группа A (Контроль) | Группа B (Тест) |
| :--- | :---: | :---: |
| **Доля успешных первых сессий (`good_session`)** | **0.316** (31.6%) | **0.315** (31.5%) |
| **Разница (B − A)** | — | **-0.001** (-0.1 п.п.) |
| **p-value (Z-тест пропорций)** | **0.578** | — |

## ✅ Выводы и бизнес-рекомендации
1. **Статистическая значимость отсутствует:** Полученное значение `p-value = 0.578` значительно превышает уровень значимости $\alpha = 0.05$. Оснований отвергнуть нулевую гипотезу нет — разница в `-0.1 п.п.` находится в пределах случайной погрешности.
2. **Рекомендация по внедрению:** **Не раскатывать** новый алгоритм рекомендаций, так как он не дает прироста вовлеченности по сравнению с текущей версией. (Ввиду отсутствия роста целевой метрики и технических логов в датасете, дополнительный расчет барьерных метрик не проводился).
3. **Дальнейшие шаги:** Оставить текущий продакшн-алгоритм. Совместно с продуктовой командой и разработкой проанализировать причины отсутствия эффекта (например, поведение алгоритма в отдельных сегментах пользователей) и сформулировать новую гипотезу для следующей итерации A/B-теста.
